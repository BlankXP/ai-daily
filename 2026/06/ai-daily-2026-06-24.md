## Trump:Anthropic"现在不是"国安威胁,但 Defense Production Act 仍在桌上

本月最大的 AI 地缘政治 saga 达成脆弱休战。Trump 接受 The Axios Show 专访时承认一周前曾视 Anthropic 为国安威胁,但表示公司"现在已经回过味来"。危机由政府指令 Anthropic 阻止所有外国国籍用户访问 Fable 5 和 Mythos 5 触发,通过 G7 峰会上 Trump 与 Dario Amodei 等科技领袖直接接触而缓解。Trump 称 Amodei 对出口管制指令"反应非常快"且"负责任"。Anthropic 发言人对 Reuters 表示:"我们感谢政府持续的合作,致力于尽快解决此事,共同保护关键基础设施并确保美国在 AI 领域领先。"但 Trump 未关闭国防生产法紧急权力选项:"我有权使用很多东西,"Trump 谈到 DPA 时说,"但我不确定必须那样做。"背景:政府部分挫败感源于 Anthropic 招募数名拜登政府官员,包括 Elizabeth Kelly(AI Safety Institute 前所长)、Tarun Chhabra(NSC 技术与国安协调员)、Ben Buchanan(拜登 AI 顾问)——裂痕既是技术也是政治。Anthropic 局势未完全解决,只是暂停:DPA 威胁仍存,外国访问 Fable 5/Mythos 5 仍受限,Anthropic 招聘实践与现政府政治偏好之间的张力未消。

点评:Trump"现在不是威胁"是 Anthropic 危机的脆弱休战,而非终结;DPA 仍"在桌上"显示政府保留紧急权力选项,招聘政治冲突的根源未解——对企业买家的教训是模型访问已不再纯粹是商业决策,需理解供应商政治暴露。原文:[Reuters](https://www.reuters.com/world/us/trump-tells-axios-he-no-longer-views-anthropic-national-security-threat-2026-06-19/) / [Axios](https://www.axios.com/2026/06/19/trump-anthropic-national-security-the-axios-show)

## 白宫 Executive Order 14409:30 天内设 AI Cybersecurity Clearinghouse,国防部长 30 天内强化信息系统

Trump 政府 6 月 2 日签署的 Executive Order 14409《促进先进人工智能创新与安全》现正产生严肃的实施活动——对关键基础设施暴露的企业影响重大。命令把 AI 安全定位为创新的"前提"而非"刹车"。核心是新设 AI Cybersecurity Clearinghouse——一个自愿的产业-政府合作机构,30 天内由财政部长会同 NSA 和 CISA 设立,扫描软件漏洞、验证并协调关键基础设施领域的补丁分发。命令正文称国防部长为"战争部长",要求 30 天内优先强化信息系统。命令原文:"美国继续在 AI 领域领先世界,因 AI 产业的巨大人才与创新,且拒绝用过度负担的监管扼杀创新。"这与 Anthropic 出口管制令形成两条平行轨道:一条是出口管制(限制谁可用),一条是 EO 14409(强化防御能力)——政府正同步推"堵"与"疏"。

点评:EO 14409 把 AI 安全从"商业合规"提升为"关键基础设施防御",30 天内设 Clearinghouse 的紧迫时间表显示政府把 AI 网络安全视为当下威胁;与 Anthropic 出口管制令构成"堵+疏"双轨,显示 AI 监管已从"事后规制"进入"事前架构"阶段。原文:[senx.ai](https://senx.ai/news/2026-06-23-daily-ai-news) / [White House](https://www.whitehouse.gov/presidential-actions/2026/06/executive-order-on-promoting-advanced-artificial-intelligence-innovation-and-security/)

## Anthropic 收购 Stainless:强化 API SDK 工具链

Anthropic 收购 Stainless,强化 API SDK 工具链。Stainless 专注于自动生成多语言 SDK,让 API 提供商可一次性发布 TypeScript、Python、Go、Java、Ruby 等多语言客户端库。这与 Anthropic 把 Claude 嵌入企业工作流的战略一致——SDK 是开发者采用 Claude 的"最后一公里",Stainless 的自动化工具链让 Anthropic 能更快支持更多语言与平台。同期 Anthropic 准备为移动应用引入 Cowork 支持,把计划任务查看与管理带入日常设备工作流;7 月 8 日起将对部分被标记但未被禁的账户要求身份验证,由 Persona 处理身份检查。Claude Code Extended Thinking 输出引发关注——可见推理文本并非原始思维链,详细推理已加密,Anthropic 持有密钥,普通用户收到摘要而非完整内部轨迹,完整访问需企业安排。

点评:Anthropic 收购 Stainless 显示 API SDK 已成为 AI 实验室开发者采用的"最后一公里";Extended Thinking 加密推理显示 Anthropic 在"agent 透明度"与"模型安全"间选择后者——审计与调试场景需把"显示推理"视为产品输出,而非完整取证记录。原文:[AI Hayami](https://ai-hayami.com/en/daily/2026-06-23) / [Anthropic](https://www.anthropic.com/news/anthropic-acquires-stainless)

## JetBrains IDE 支持 Claude 与企业自定义 agent,Vercel 开源 Eve 框架

JetBrains IDE 支持 Claude 与企业自定义 agent,把 Claude Code 的能力带入 IntelliJ/PyCharm/WebStorm 等 JetBrains 生态。这与 GitHub Copilot 桌面应用 GA、Apple Xcode 27 引入 agentic 编码、AWS Kiro 推到 iPhone 形成同一趋势:agentic 编码正从单一 IDE 扩展到全平台。同期 Vercel 开源 Eve 框架,把文件目录变成 agent——把系统指向工作区,让目录结构成为 agent 操作上下文的一部分。这契合"agent 住在项目里而非漂浮其上"的更广运动:文件感知 agent 可读取约定、在可预测位置保存状态,与 Block Builderbot 的 Slack 内 agent 编排层、Anthropic 的 Claude Code Artifacts 形成同一架构方向。同期 Ampersend 智能体支付路由层上线,把支付决策从用户手动选择转为 agent 自动路由。

点评:JetBrains 支持 Claude 与 Vercel 开源 Eve 显示 agentic 编码正从"单一 IDE"扩展到"全平台+文件感知";agent 从"漂浮在项目之上"到"住在项目里"是 AI 编码工具的架构转向——文件目录成为 agent 的操作上下文。原文:[AI 天天酱](https://www.bilibili.com/video/BV1CAj26yEvP/) / [Iris AI Digest](https://podcasts.apple.com/us/podcast/ai-digest-june-23-2026/id1888042569?i=1000773888614)

## Shift 机器人训练清洁队纽约登场:付钱让清洁工允许摄像头进家庭收集训练数据

初创公司 Shift 在纽约派出"机器人训练清洁队"——付钱让清洁工允许摄像头进入家庭,在清洁过程中收集机器人训练数据。这是具身智能数据收集的"激进现场化"路径:相比在实验室模拟家庭环境,直接进入真实家庭收集数据可大幅提升机器人在真实物理环境的泛化能力。但隐私争议巨大:家庭是最私密的空间,清洁工"同意"是否能代表家庭成员同意?摄像头捕捉的儿童、室友、访客图像如何处理?这与 Signal 总裁 Meredith Whittaker 警告"AI Agent 是隐私后门"形成直接冲突。同期 NVIDIA ENPIRE 框架让 AI Agent 自主做机器人研究,世界经济论坛 2026 十大新兴技术把具身智能+AI 驱动科学发现上榜,显示技术回归物理世界。

点评:Shift 机器人训练清洁队是具身智能数据收集的"激进现场化"路径——直接进入真实家庭收集数据可提升泛化能力,但隐私争议巨大;当清洁工"同意"无法代表家庭成员同意,具身智能的数据治理成为新的伦理难题。原文:[senx.ai](https://senx.ai/news/2026-06-23-daily-ai-news)

## GPT-5.6 传言:6 月 25 日发布,2M token 上下文,价格下探 Anthropic

未确认的 OpenAI 传言指向 6 月 25 日可能发布 GPT-5.6,声称 200 万 token 上下文窗口、更低定价、更强 agentic 编码、更强图像到代码复现、更干净前端生成、ChatGPT 内浏览器式测试。把这些细节当传言,直到 OpenAI 确认。即便作为传言,其形状有用:竞赛正走向能检查界面、使用工具、测试自身输出、从错误恢复的模型。编码模型不再仅以"能否写函数"评判,而以"能完成多少构建-检查-修订循环"评判。这与 Sakana Fugu 的多 agent 编排、Block Builderbot 的 Slack 内 agent 工厂形成同一趋势:AI 编码正从"代码补全"演进到"工程闭环"。OpenAI 首席科学家 Jakub Pachocki 内部把 GPT-5.6 描述为相对 GPT-5.5 的"有意义改进"。当前 GPT-5.5 在 SWE-bench Pro 上得分 58.6,落后 GLM-5.2(62.1)和 Claude Opus 4.8(61.4)。
